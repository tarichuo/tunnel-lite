# Tunnel Lite V1.0 产品设计

本文基于仓库中的 `PRD.md`，将需求细化为可用于界面设计与开发的产品方案。原 PRD 保持不变。D1—D3 已由用户确认（2026-11-03），纳入 V1.0 设计基线；其余新增行为作为设计建议供评审。

## 1. 产品目标与范围

帮助有公网服务器的开发者，以尽量少的操作将本机 TCP 服务暴露到公网，并在断网后自动恢复。

核心体验：接入 Agent → 创建映射 → 复制公网地址 → 查看状态 → 按需下线。

设计原则：

- 首次使用有明确的下一步，每一步能判断是否完成。
- 状态解释具体，失败时给出可执行的处理方式。
- 页面优先展示连接和端口信息，减少装饰性图表。
- 运行成本可控，沿用 Go 单程序、SQLite、原生 HTML/CSS/JS 与 5 秒轮询。

V1.0 范围：TCP 映射、Agent 接入、管理登录、映射管理、基础操作记录。暂不加入 HTTP 域名路由、UDP、流量计费、团队权限、实时流量图表、在线终端、自动证书签发。

### 已确认决策（2026-11-03）

| 编号 | 问题 | 已确认方案 | 对设计的影响 |
|---|---|---|---|
| D1 | 单管理员还是多用户隔离？ | 单管理员或小团队共用入口 | 不设计账号体系、成员列表、资源归属权限 |
| D2 | 主动下线后能否再次启用？ | 保留记录并允许启用 | 增加启用操作；按自动分配或指定端口策略处理冲突 |
| D3 | 如何创建 Agent 身份？ | 网页添加 Agent 并生成专属 Token | 增加轻量接入向导及创建 Agent 接口 |

以上三项已确认，无需再次确认。下文按单管理员、可再次启用映射、网页签发 Agent Token 的方案展开。

## 2. 信息架构

Web 管理端采用单页应用结构，无需独立前端服务。

```text
登录
└── 管理台
    ├── 映射（默认首页，包含概览统计）
    │   ├── 创建映射抽屉
    │   ├── 映射详情抽屉
    │   └── 下线确认弹窗
    └── Agent
        ├── 添加 Agent 向导
        └── Agent 详情抽屉
```

系统配置沿用 YAML 文件；V1.0 不增加设置中心。操作记录放在映射或 Agent 详情内，不增加单独的日志平台。

桌面端左侧窄导航、右侧内容；窄屏改为顶部导航。顶部固定显示产品名、服务器地址、数据更新时间和退出入口。

## 3. 首次使用流程

### 3.1 服务端部署与登录

1. 管理员准备服务端配置、管理 Token、TLS 证书、公网访问地址和允许使用的端口池。
2. 启动服务端，访问 Web 管理端，输入管理 Token 登录。
3. 登录成功进入映射页。没有 Agent 时展示接入引导，主按钮为“添加 Agent”。

登录页仅保留产品标识、管理 Token 输入框、显示/隐藏按钮、登录按钮和错误提示。提交时禁用重复点击；认证失败统一提示“管理 Token 无效”，不回显输入值。

Web 登录建议由服务端校验管理 Token 后创建会话，使用 HttpOnly、Secure、SameSite Cookie；管理 Token 不写入 localStorage 或 URL。会话接口需补充至原 API 设计，写操作需校验同源并防范 CSRF。管理页面与 API 的对外访问使用 HTTPS，可由现有反向代理终止 TLS。

### 3.2 接入 Agent

向导分为三步：

1. **命名与授权**：填写名称；默认仅允许转发到 `127.0.0.1`，可显式配置允许的目标 IP。自动生成 Agent ID 与独立 Token。
2. **安装与配置**：按 Linux / macOS / Windows 展示对应二进制下载说明、配置示例和启动命令；展示服务端地址与 CA 文件配置。未提供真实发布文件时不得放置虚假下载链接。
3. **等待连接**：轮询 Agent 状态。连接成功后展示“Agent 已在线”，提供“创建第一个映射”。等待超时保留页面，并提示检查地址、Token、CA 与网络。

Token 仅创建时展示一次，可复制配置。页面说明“关闭后无法再次查看，请妥善保存”。服务端仅保存哈希。此页面响应禁止缓存，日志不得记录完整 Token。

目标限制需由 Agent 本地配置再次约束，服务端请求不能扩大 Agent 的本地授权范围；页面说明公网管理员将具备创建映射的权限。

网页为 V1.0 的 Agent 身份创建入口；用户在本地启动 Agent，使用网页提供的配置完成接入。命令行签发身份不作为 V1.0 必需功能。

## 4. 页面设计

### 4.1 映射首页

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Tunnel Lite       公网服务器 1.2.3.4         更新于 15:20:05   退出 │
├──────────┬───────────────────────────────────────────────────────────┤
│ 映射     │ 在线 Agent 2    有效映射 4    运行中 3    需处理 1       │
│ Agent    │                                                           │
│          │ 映射                          刷新          + 创建映射    │
│          │ [搜索名称 / 地址] [状态：全部] [Agent：全部]             │
│          │ 名称 / ID  Agent  本地目标  公网地址  状态  操作         │
│          │ web        dev01  ...:3000  ...:18080 运行中  详情 下线 │
│          │ api        dev02  ...:8080  ...:18081 已断开  详情 下线 │
└──────────┴───────────────────────────────────────────────────────────┘
```

统计卡口径：

| 指标 | 口径 |
|---|---|
| 在线 Agent | 当前控制连接认证成功且未超时的 Agent 数 |
| 有效映射 | 期望保持启用的映射数，包含启动中、运行中、断开及启用失败的记录 |
| 运行中 | `ACTIVE` 数量 |
| 需处理 | 期望启用且状态为 `OFFLINE` 或 `ERROR` 的数量 |

表格默认隐藏已下线记录，可在状态筛选中查看。未启用筛选时按创建时间倒序排列；轮询保持现有顺序、筛选、页码和展开状态。异常由醒目状态和“需处理”卡片引导查看，避免自动重排造成误点。

每行展示映射名称、Agent 名称、本地 IP:端口、公网地址、状态、详情及主操作。公网地址旁有复制按钮，成功反馈“地址已复制”，失败时展示可选中的完整文本。TCP 地址不默认渲染为网页链接。

搜索按映射名称、ID、Agent 名称及地址匹配；状态和 Agent 使用下拉筛选。列表建议每页 20 条。

空态区分：

- 无 Agent：说明需要先接入本地机器，进入接入流程。
- 有 Agent、无映射：展示“创建第一个映射”。
- 筛选无结果：展示“清除筛选”。
- 请求失败：保留上次数据，标注“数据可能已过期”，提供重试。

### 4.2 创建映射

桌面端使用右侧抽屉，窄屏全屏表单。字段顺序遵循“在哪台机器 → 转发到哪里 → 从哪里访问”。

| 字段 | 默认值与规则 | 帮助文案 |
|---|---|---|
| Agent | 必选；从 Agent 详情进入时预选 | 只允许选择在线 Agent；离线项显示原因 |
| 映射名称 | 必填，去首尾空格，1—64 字符 | 同一 Agent 内名称唯一，避免操作时混淆 |
| 协议 | 固定 TCP，只读 | V1.0 仅支持 TCP |
| 本地 IP | 默认 `127.0.0.1`，必须为合法 IP | 此地址相对于 Agent 所在机器 |
| 本地端口 | 必填，整数 1—65535 | 例如本机开发服务使用 3000 |
| 公网端口方式 | 默认“自动分配” | 从服务端配置的端口池中分配 |
| 指定公网端口 | 仅选择“指定端口”时展示 | 必须在端口池内且未被占用 |

目标 IP 需要同时满足服务端策略与 Agent 本地允许列表。V1.0 暂不支持目标域名，避免 DNS 变化导致目标授权语义不清。

提交区显示“公网可访问此 TCP 服务，请确认目标服务已有适当的认证措施”。此处为表单帮助文本，不新增单独确认步骤。

交互规则：

1. 前端校验字段后提交，按钮显示“正在创建”，保留输入并防止重复提交。
2. 服务端异步创建时返回 `STARTING`；抽屉关闭，列表插入记录，提示“映射正在启动”。
3. Agent 确认配置且公网监听成功后转为 `ACTIVE`，可以复制公网地址。
4. 校验失败在字段旁提示；端口冲突提示“该公网端口已被占用，请更换或使用自动分配”。
5. 请求超时保留表单并允许查询创建结果；重试沿用同一幂等键，避免产生重复映射。
6. 提交前 Agent 变为离线时保留输入，提示等待 Agent 上线或改选 Agent。

公网地址尚未就绪时不显示可复制的可用地址；创建中或异常状态即便已分配端口，也应注明当前不可用。

### 4.3 映射详情

展示名称与 ID、状态解释、Agent、本地目标、公网地址、端口分配方式、创建时间、最近状态变化时间及最近错误。

下方展示最近 20 条关键操作：创建、启动成功、Agent 断开、恢复、下线和失败。仅记录状态转换，不将每次心跳或数据连接写入操作记录。

`ACTIVE` 的说明为“Agent 在线且公网端口已监听”。它不承诺本地服务健康；本地服务拒绝连接时记录最近转发失败原因，页面显示辅助提示，映射状态保持 `ACTIVE`。不进行持续的本地服务健康探测。

### 4.4 下线映射

`STARTING`、`ACTIVE`、`OFFLINE` 及期望启用的 `ERROR` 均允许下线。

确认弹窗展示映射名称、公网地址和后果：“下线将关闭监听、断开此映射的现有连接并释放公网端口。”按钮为“取消”和“下线映射”。

成功后保留记录并显示 `STOPPED`；当前筛选不包含下线记录时移出列表，提示“映射已下线”。接口失败时保持当前记录并展示错误，不能提前显示成功。

### 4.5 再次启用

- 自动分配的映射：优先尝试原端口，若已被占用则重新分配，并明确告知新地址。
- 指定端口的映射：原端口不可用时保持下线，提示更换端口；不静默切换。
- 启用前展示将使用的配置，成功后进入 `STARTING`。
- Agent 离线时禁用启用操作，并说明原因。

V1.0 不提供运行中修改本地目标；通过下线并创建新映射处理。再次启用时仅允许调整已释放的公网端口策略。

### 4.6 Agent 列表与详情

列表字段：名称、ID、状态、最后心跳、有效映射数、详情入口。状态区分“待接入”“在线”“离线”；新签发但从未连接的 Agent 显示待接入，最后心跳显示“尚未连接”。

详情展示控制连接状态、最近连接时间、最后心跳、允许的目标范围和所属映射列表。在线 Agent 可直接“创建映射”；离线时提示先检查 Agent 进程和网络。

心跳时间同时提供相对时间与完整时间，统一使用浏览器本地时区并标注。Agent 名称不充当身份标识；同名机器通过 ID 区分。Token 不在详情中展示。

## 5. 状态与端口规则

仅靠一个状态字段无法清楚表达“用户希望启用，但重启恢复失败”。建议保存期望状态 `enabled`，运行状态作为单独维度；恢复逻辑依据期望状态，不能根据上一次 `ACTIVE` 记录直接认定可用。

| 运行状态 | 页面文案 | 典型原因 | 端口处理 | 用户操作 |
|---|---|---|---|---|
| STARTING | 启动中 | 已提交，等待监听与 Agent 确认 | 临时预留 | 详情、下线 |
| ACTIVE | 运行中 | 控制连接在线、监听就绪、配置确认 | 持续占用 | 复制、详情、下线 |
| OFFLINE | Agent 已断开 | 启用中的映射失去 Agent 连接 | 持续预留 | 详情、下线 |
| STOPPED | 已下线 | 用户主动停止，`enabled=false` | 释放 | 详情、启用 |
| ERROR | 启动或恢复失败 | 端口冲突、配置拒绝、监听失败 | 视失败阶段回滚；显示是否仍预留 | 详情、下线；再次启用 |

关键规则：

- 新创建失败：撤销监听和临时端口预留，保留错误记录；初始失败设置 `enabled=false`。
- Agent 临时断开：保持原端口预留及可用时的监听，对新连接快速关闭，不无限排队；已有受影响连接结束后不回放应用数据。
- 恢复失败：保留 `enabled=true` 与原端口逻辑预留，显示 `ERROR`；用户主动下线后释放。
- Agent 重连：校验原身份，同步期望启用的配置，确认后恢复 `ACTIVE`。
- Server 重启：重建期望启用映射的端口预留，重新绑定监听；等待 Agent 时显示 `OFFLINE`，确认后 `ACTIVE`。端口被其他程序占用则显示 `ERROR`，不擅自换端口。
- 下线与重连同时发生：下线优先，Agent 收到最新配置版本，已下线映射不得因旧确认消息重新启用。
- 离线默认持续保留端口，不自动过期，遵循 PRD；端口池耗尽时提示检查离线映射并下线不再需要的记录。
- 创建中等待确认建议超时 10 秒；超过期限按创建失败回滚。此为产品建议，可由配置调整。

## 6. PRD 中需要补充的接口与配置

保留原有 `/api/v1` 路径，开发前需补充以下契约：

| 内容 | 建议 |
|---|---|
| Web 登录与退出 | 增加会话创建、查询与删除接口；API 客户端继续使用独立管理 Bearer Token |
| Agent 身份创建 | `POST /agents` 返回 Agent ID 与仅展示一次的 Token，供网页接入向导使用 |
| 映射创建 | 支持 `202 + STARTING`，明确异步确认；保留同步完成时返回 `201 + ACTIVE` 的可能 |
| 列表查询 | 支持搜索、状态、Agent、分页及总数；统计不随当前页变化 |
| 下线 | 原 `DELETE /tunnels/{id}` 定义为幂等软下线，记录仍可查询；重复下线成功返回 |
| 再次启用 | 增加 `POST /tunnels/{id}/start`，支持冲突时的端口选择 |
| 操作记录 | 详情返回最近记录，或增加按资源查询的只读接口 |
| 前端可读配置 | 提供公网地址、端口池及配额，不返回 Token、私钥或内部文件路径 |
| 一致错误格式 | `{error: {code, message, field?, request_id}}`；前端按错误码展示中文 |
| 创建幂等 | 接受幂等键，说明有效期和重复请求返回规则 |

`remote_port` 与响应中的 `public_port` 在原 PRD 中名称不同：V1.0 建议保持原契约，界面统一称“公网端口”，接口文档注明对应关系。

建议错误码包括：`UNAUTHORIZED`、`AGENT_OFFLINE`、`PORT_IN_USE`、`PORT_POOL_EXHAUSTED`、`TARGET_NOT_ALLOWED`、`AGENT_TUNNEL_LIMIT`、`START_TIMEOUT`。HTTP 状态码与业务错误码应分别定义，端口检查以实际绑定及数据库约束结果为准。

需新增或明确的配置：公网展示地址 `public_host`、控制连接 TLS 证书与 Agent CA、管理端 HTTPS 接入方式、Agent 映射上限、单映射并发上限、服务端总连接上限、待配对连接超时和日志保留策略。公网展示地址不能仅依赖网卡自动识别，云服务器可能使用 NAT。

数据通道建议复用 7001 的 TLS 入口，通过首帧区分控制与数据连接，避免增加部署端口。除 Agent、Tunnel、Connection ID 关联外，数据连接需验证一次性且短期有效的配对凭证，不能把 Connection ID 本身当作认证凭据。

## 7. 视觉与交互规范

- 气质：简洁、清晰的运维控制台，浅灰背景、白色内容面板、蓝色主操作。
- 正常绿色、处理中蓝色、断开橙色、失败红色、下线灰色；所有状态同时使用文字，不能只依赖颜色。
- 正文建议 14px，标题 20—24px；IP、端口、ID 使用等宽字体，复制区域留足点击空间。
- 状态和地址优先保证可读，较长名称可截断并提供完整内容；详情显示完整值。
- 主要按钮文案使用明确动作：“创建映射”“复制地址”“下线映射”。
- 表单标签常驻显示，必填项有标记，报错后定位首个错误字段。
- 抽屉与弹窗支持键盘操作、焦点管理及 Escape 关闭；表单有未保存内容时关闭需提示。
- 窄屏将列表转为卡片，按名称/状态、公网地址、本地目标/Agent、操作的顺序展示。

## 8. 刷新、失败与资源约束

前台页面每 5 秒轮询当前页面所需数据，Agent 接入等待页沿用相同周期。后台标签暂停轮询，返回前台立即刷新。请求耗时超过周期时不叠加新请求。

轮询不覆盖表单内容，不关闭弹窗，不自动移动焦点。连续失败显示常驻提示和最后成功更新时间；恢复后自动清除。认证过期跳转登录，不在浏览器持久保存含凭证的内容。

服务端限制连接总量和缓冲区使用；单映射达到并发上限时拒绝新增连接，现有连接继续。数据通道配对超时后关闭两端相关连接并释放资源。错误记录需限频，防止连接失败引发日志增长。

操作记录建议保留 30 天并设置总量上限，日志按大小轮转；具体容量参数需在稳定性测试后确定，不能仅凭“2GB 内存”承诺并发能力。

## 9. 验收场景

| 场景 | 预期结果 |
|---|---|
| 首次登录且没有 Agent | 显示接入引导，能识别需要执行的下一步 |
| Agent 使用有效 Token 与 CA 接入 | 列表显示在线，连接信息与心跳更新 |
| Token 或证书无效 | Agent 给出明确原因；管理端不显示为已在线 |
| 创建自动端口映射 | 展示启动进度，确认后运行，复制所得地址能连接到目标 |
| 指定端口已占用 | 显示冲突，保留输入，无残留监听或额外记录 |
| 创建后 HTTP 响应丢失并重试 | 同一幂等键仅产生一个映射 |
| Agent 断网超过心跳超时 | 下一次成功轮询显示断开，原端口仍被预留 |
| Agent 使用原身份重连 | 期望启用的映射恢复，公网端口不变 |
| 本地服务未启动 | 显示最近转发失败原因，不把 Agent 误判为离线 |
| 对运行中的映射下线 | 明示并关闭现有连接，释放端口，保留可查询记录 |
| 下线时 Agent 恰好重连 | 最终保持下线，旧配置确认不能复活映射 |
| 再启用时原端口被占用 | 自动分配项明确提示新地址；指定端口项要求重新选择 |
| Server 重启 | 启用配置恢复，下线配置保持下线；真实冲突展示错误 |
| 达到映射或连接上限 | 给出可理解的错误，既有正常映射继续运行 |
| 页面轮询失败或会话过期 | 数据过期有提示；认证失效进入登录页 |
| 目标地址超出授权范围 | 服务端或 Agent 拒绝，不建立目标连接 |

## 10. 实施顺序

1. 按已确认的 D1—D3 细化接口契约，并落实状态语义和端口恢复规则。
2. 完成认证、TLS、Agent 身份、心跳、单条映射与数据通道配对，打通端到端 TCP 访问。
3. 加入持久化、断线恢复、重启恢复、端口分配和配额控制。
4. 实现 Web 登录、接入、映射创建/列表/详情/下线，再补筛选及操作反馈。
5. 按验收场景完成故障、并发和长时间运行验证，再确定公开的容量建议。
